# .NET Launcher — дизайн (v2: самостоятельный лаунчер)

Дата: 2026-11-19 · Статус: согласовано в разговоре (v1 утверждена, дополнения — решения пользователя)

## Зачем
PineconeMC (форк Prism/ElyPrism) выглядит устаревшим: его Qt 6.10 зашита в AppImage без блюра KDE и Kvantum,
анимаций нет. Пользователь хочет красивый современный лаунчер: **блюр, голубой основной цвет, без неона,
красивые анимации, удобная работа со сборками**. В процессе добавил: **Windows и Linux**, **сборку
можно скачать только через лаунчер**, друзья входят через **Ely.by**, хостинг на **GitHub**.

Поэтому лаунчер не оболочка над PineconeMC, а самостоятельная программа: сам ставит Minecraft, NeoForge
и Java, сам скачивает и обновляет сборку «.NET», сам запускает игру.

## Цели
- **Каталог сборок** (запрос пользователя 19.11): автор публикует не только обновления, но и новые сборки; игроки сразу видят их в «Доступные сборки» и ставят одной кнопкой. У сборки может быть адрес сервера → кнопка «Играть на сервере».
- Одна программа для Windows и Linux: вход Ely.by → «Установить .NET» → «Играть».
- Обновления сборки приходят сами: автор публикует, друзья получают при следующем запуске
  (докачиваются только изменённые файлы).
- Стекло с блюром (KDE на Linux, Acrylic/Mica на Windows), голубой акцент, плавные анимации.
- Моды, ресурспаки, шейдеры: список с иконками, вкл/выкл, поиск по Modrinth под версию сборки,
  установка в один клик с зависимостями и без дублей, проверка обновлений.
- Снимок перед каждым изменением, откат одной кнопкой.
- Режим автора: собрать текущую сборку и опубликовать обновление на GitHub одной кнопкой.

## Не цели (v1)
- Вход через Microsoft (нужно одобрение Mojang).

(19.11 пользователь добавил: **CurseForge как второй источник модов** — поиск по ключу автора, игроки качают с CDN без ключа; **смена скина** — предпросмотр на модели + загрузка на Ely.by.)
- Произвольные чужие сборки: лаунчер сделан под «.NET», но формат позволяет добавить другие позже.
- Подпись `.exe` сертификатом: Windows покажет «неизвестный издатель», друзьям придётся нажать
  «Подробнее → Выполнить в любом случае».
- Неон и киберпанк в оформлении лаунчера (это стиль игры).

## Анти-цели
- Сломать сборку или мир: ни одного изменения модов без снимка; обновление не трогает `saves/`,
  `options.txt`, скриншоты и моды, добавленные игроком.
- Перезаливать чужие моды с закрытой лицензией.
- Тормоза: в простое CPU около 0, анимации плавные на 320 Гц.
- Хранить пароль: храним только токены Ely.by.

## Ограничения и факты (проверено 19.11)
- `minecraft-launcher-lib` 8.0 (BSD, Python ≥3.10): установка версий, NeoForge (`mod_loader/_neoforge.py`),
  Java-рантайм Mojang, команда запуска, `.mrpack`.
- Ely.by: Yggdrasil API `https://authserver.ely.by/auth/{authenticate,refresh,validate,invalidate}`,
  2FA передаётся как `пароль:код`. В игре: `-javaagent:authlib-injector.jar=ely.by`
  (authlib-injector качаем с `authlib-injector.yushi.moe`, проверяем sha256).
- Сборка сейчас: `~/.local/share/ElyPrismLauncher/instances/1.21.1`, NeoForge 21.1.267, 123 мода.
  118 есть на Modrinth (по sha1). Не на Modrinth: 4 мода с лицензией **MIT** (Cinematic Interaction,
  CineCreate, Cinematic Cookery, Cinematic Delight), их можно класть в релиз с указанием авторов, и
  **Create: Chromeware 1.3.0 — All Rights Reserved**, перезаливать нельзя (см. «Особые моды»).
- Блюр KDE: ctypes `KWindowEffects::enableBlurBehind` из `libKF6WindowSystem.so.6` (рабочий код в
  `~/.local/share/glasscontrol/glasscontrol.py: enable_blur`), вызывать после каждого show. Windows 11:
  `DwmSetWindowAttribute(DWMWA_SYSTEMBACKDROP_TYPE=38, DWMSBT_TRANSIENTWINDOW=3)` + тёмный режим;
  Windows 10: `SetWindowCompositionAttribute` (ACCENT_ENABLE_ACRYLICBLURBEHIND). Нет блюра → непрозрачный
  тёмно-синий фон.
- `.exe` нельзя нормально собрать на Linux, его собирает GitHub Actions (windows-latest, PyInstaller).
  Linux-сборка там же (ubuntu, PyInstaller onedir → tar.gz); локально можно запускать из исходников.
- Modrinth API с общим User-Agent, без личных данных.

## Подходы
| | Что | Плюсы | Минусы |
|---|---|---|---|
| А | Тема (QSS) для PineconeMC | быстро | нет блюра и анимаций; не решает «только через лаунчер» |
| Б1 | Оболочка над PineconeMC | меньше кода | у друзей на Windows нужен ещё и PineconeMC |
| **Б2** | **Самостоятельный лаунчер (PySide6 + minecraft-launcher-lib)** | одна программа, полный контроль | больше работы |
| В | Пересборка PineconeMC | всё в одной программе | большой C++, правки при каждом обновлении |

Пользователь выбрал Б; после «Windows + Linux» и «только через лаунчер» это Б2.

## Решения пользователя
Свой лаунчер · блюр · голубой · без неона · анимации · удобные моды · Windows + Linux · сборка только
через лаунчер · вход Ely.by · хостинг GitHub.

## Мои решения (можно поправить)

### Формат сборки и публикация
- Формат — стандартный **`.mrpack`** (Modrinth): `modrinth.index.json` (моды по ссылкам Modrinth CDN + sha1/sha512)
  + `overrides/` (наши конфиги, FancyMenu, ресурспаки, шейдер-пресет, MIT-моды, позже ядро). Плюс: такой файл
  умеет импортировать и PineconeMC.
- На GitHub (публичный репозиторий, имя предложу при создании) лежат исходники лаунчера и сборки.
  Каждое обновление = Release: `net-<версия>.mrpack`, `channel.json` (версия сборки, список изменений,
  последняя версия лаунчера, ссылки на exe/tar.gz). Лаунчер читает
  `…/releases/latest/download/channel.json`.
- Обновление у игрока: сравнение по sha1, качаются только новые и изменённые файлы, удаляются только
  файлы, поставленные прошлой версией сборки (учёт в `pack-state.json`). Не трогаем `saves/`,
  `options.txt`, `screenshots/`, моды игрока. Конфиги из `overrides/` перезаписываются, кроме списка
  `preserve` в манифесте.
- Режим автора (включается в настройках): «Собрать обновление» берёт рабочую сборку, сопоставляет jar с
  Modrinth по sha1, остальное кладёт в overrides (только разрешённые лицензии, иначе предупреждение),
  показывает разницу с прошлой версией и поле для списка изменений. «Опубликовать» создаёт Release через
  GitHub REST API с токеном пользователя (хранится локально).

### Особые моды (не на Modrinth, закрытая лицензия)
- В манифесте `manual`: имя, sha1, ссылка на страницу автора. Если файла нет, лаунчер показывает шаг
  «Скачай вручную → перетащи сюда» и проверяет sha1. Сейчас это Chromeware. Можно спросить автора о
  разрешении — тогда переедет в обычный список.

### Хранение
- Данные: Linux `~/.local/share/net-launcher/`, Windows `%APPDATA%\NET Launcher\`. Внутри: `minecraft/`
  (версии, библиотеки, ассеты, Java), `instances/net/` (папка игры), `snapshots/`, `cache/`,
  `settings.json`, `accounts.json` (токены Ely.by, права 600 на Linux).
- Перенос у автора: при первом запуске предложить импорт из PineconeMC `instances/1.21.1` (моды, конфиги,
  миры, скриншоты, options). PineconeMC остаётся как был.

### Окно и разделы
```
┌──────┬───────────────────────────────────────────────┐
│  ◆   │  [фон: скриншоты сборки, медленный наезд]     │
│ Глав │                                               │
│ Моды │   .NET                       v0.3 · вышло     │
│ Ресур│   NeoForge 1.21.1 · 123 мода   обновление ↓   │
│ Шейд │   ┌─────────────────┐  Продолжить:            │
│ Сним │   │     ИГРАТЬ      │  «Новый мир» →          │
│ Наст │   └─────────────────┘                         │
│ ●shar│   Что нового: …                               │
└──────┴───────────────────────────────────────────────┘
```
- **Первый запуск:** приветствие → вход Ely.by (логин/пароль, ссылка «Создать аккаунт») → установка
  (Minecraft, NeoForge, Java, моды) с общим прогрессом и скоростью → «Играть».
- **Главная:** фон из скриншотов (иначе голубой градиент), название, версия сборки, «вышло обновление»,
  «Играть», «Продолжить: <последний мир>» (quickPlay), «Что нового», аккаунт со скином-головой.
- **3D-модель игрока** (запрос пользователя 19.11): справа на главной объёмная фигура со скином Ely.by (тонкие руки для slim-скинов, второй слой), крутится мышью, в покое слегка «дышит» и покачивается.
- **Тексты интерфейса** проходят через skill unslop (запрос пользователя 19.11).
- **Запуск:** статус «Проверка файлов → Запуск → Загрузка модов (по логу) → В игре». Окно прячется в
  трей и возвращается после выхода. Вылет → коротко что случилось + «Открыть отчёт».
- **Моды / Ресурспаки / Шейдеры:** список с иконками; моды сборки помечены значком сборки (выключать
  можно только клиентские, иначе не пустит на сервер); «Найти» — карточки Modrinth, «Установить»;
  зависимости ставятся сами, дубль по modId (в т.ч. внутри другого jar) не ставится; «Проверить
  обновления» (Modrinth `version_files/update`, бету не предлагать вместо релиза).
- **Снимки:** список, «Откатить», «Удалить».
- **Настройки:** память (ползунок, рекомендация от объёма ОЗУ), разрешение/полный экран, анимации
  вкл/выкл, папка данных, режим автора, «Открыть папку игры», выход из аккаунта.

### Вид
- Фон окна `rgba(12,18,32,0.72)` + блюр; карточки `rgba(255,255,255,0.06)` с тонкой рамкой
  `rgba(255,255,255,0.08)`; акцент `#4C9AFF` (наведение `#6AAEFF`, нажатие `#3A86F0`); текст `#E8EEF8`,
  вторичный `#9AA8BF`; скругления 14–18 px; мягкие тени; никаких свечений.
- Безрамочное окно со своими кнопками свернуть/закрыть и перетаскиванием за верхнюю область.
- Анимации: открытие окна (0.97→1 + проявление), смена страниц (сдвиг 24 px + проявление, 220 мс,
  OutCubic), наведение (цвет + подъём 1–2 px, 120 мс), каскад строк (шаг 30 мс, максимум 12 строк),
  «дыхание» градиента «Играть», плавные прогресс-бары. Всё отключается в настройках.

Разбивка на модули, кэш иконок, фоновые задачи (QThreadPool/QThread), SVG-иконки, разбор прогресса
из `latest.log`, детали Actions-workflow, иконка приложения.
